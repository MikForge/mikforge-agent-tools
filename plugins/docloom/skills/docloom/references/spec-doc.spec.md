# 产物 Spec 规范

定义产物 spec 的标准结构和规则格式。所有产物 spec 文件（如 plan.spec.md、design.spec.md）必须遵守本文档。

---

## 目的

确保所有产物 spec 文件在顶层结构、规则格式、章节命名上保持一致，下游工具（author、reviewer、fix）可稳定解析。

## 非目的

不定义各文档类型的专属章节内容或业务规则。

## 参数声明

- `无外部输入参数`
  - 类型：—
  - 必填：—
  - 默认值：—
  - 说明：本规范定义的是产物 spec 文件的内部格式约束。

## 输出声明

产物 spec 名称 `<doc_type>.spec.md`。

## 结构声明

产物 spec 文件采用 3 段式结构：

| 段 | 名称 | 说明 |
| -- | ---- | ---- |
| 1 | Frontmatter | YAML 头部，`type: spec-doc` |
| 2 | 元信息 | 6 个 `##` 级章节（目的、非目的、输入参数声明、产出文件命名、结构声明、必要章节） |
| 3 | 规则集 | `---` 分隔线后，`### XXX-NNN` 编号规则按必要章节分组排列 |

### 段1：Frontmatter

产物 spec 文件头部 YAML frontmatter，`type` 固定为单值字符串 `spec-doc`。`---` 分隔线后紧跟正文第一行，中间无空行。

**正例：**

```yaml
---
type: spec-doc
---
# 标题
```

**反例：**

```yaml
---
type: [spec-doc, design]
---
```

问题：`type` 为数组而非单值；分隔线后有空行。

### 段2：元信息

6 个 `##` 级章节（目的、非目的、输入参数声明、产出文件命名、结构声明、必要章节）彼此同级排列，位于 Frontmatter 之后、规则集之前。

#### 输入参数声明格式

每个参数独立一行：`- **`name`** — type，必填/可选，默认：值。说明。`。无默认值时省略"默认："段。无外部输入参数时写 `- 无外部输入参数`。禁止纯自然语言段落式罗列参数或将单个参数拆成多层嵌套列表。

**正例：**

```markdown
## 输入参数声明

- **`type`** — string，必填。文档类型 design。
- **`context`** — string，可选。用户提供的结构化上下文。
```

**反例：**

```markdown
## 参数声明

- `doc_type`
  - 类型：string
  - 必填：是
  - 默认值：—
  - 说明：文档类型标识，如 `plan`。
```

违规说明：单个参数拆成多层嵌套列表。应采用逐行格式，每个参数一行写完：`- **`name`** — type，必填/可选。说明。`。

### 段3：规则集

`---` 分隔线后为规则集。每条规则是独立的 `### XXX-NNN：规则标题`（`XXX` 为文档类型三字母前缀，`NNN` 为三位递增编号），按必要章节分组排列，末尾无 `## 审查列表` 章节。

**正例：** `design.spec.md` 以 `### DSG-001` ~ `### DSG-022` 结尾。

**反例：** 缺少 `---` 分隔线，或仍用旧式 `#### 规则N` 而非 `### XXX-NNN` 编号格式，或末尾多出 `## 审查列表` 章节。

违规说明：产物 spec 结构不符合编号规则格式，reviewer 无法按统一编号引用规则。

#### 规则字段

每条规则正文含三个必填字段：

- `**严重度：**` — 严重/重要/轻微
- `**约束：**` — 一句浓缩约束描述
- `**检查：**` — 审查时逐项核对，可标注严重度

#### 正反例

若约束有对应示例，以 `> **正例：**` / `> **反例：**` blockquote 附在规则末尾。正例在前，反例在后。blockquote 为可选——无独立正反例的规则可省略。

**正例：**

```markdown
### DSG-001：必需结构 — 问题陈述
- **严重度：** 严重
- **约束：** 设计文档必须包含问题陈述，一句话说明要解决的技术问题或要达成的技术目标。反例——仅写"登录太慢了需要优化"而无具体技术问题和量化指标。
- **检查：** 问题陈述清晰：设计要解决什么问题？（严重）

> **正例：**
>
> 用户登录接口在高并发场景下响应时间超过 3s，需要重新设计会话管理方案。
>
> **反例：**
>
> 登录太慢了，需要优化一下。
```

**反例：**

```markdown
#### 规则1：问题陈述必须清晰

**正例：**

## 问题陈述
登录接口 P99 延迟超 3s...

**反例：**

登录太慢了

违规说明：登录太慢缺少技术指标。
```

违规说明：旧式 `#### 规则N` 标题与正反例代码块散落。应采用 `### XXX-NNN：标题` 编号 + `严重度/约束/检查` 三段式 + `>` blockquote 正反例。

## 必要章节

产物 spec 文件必须包含以下 6 个 `##` 级章节（彼此同级）：

| 章节 | 说明 |
| ---- | ---- |
| 目的 | 该文档类型要确保什么 |
| 非目的 | 该文档类型不覆盖什么 |
| 输入参数声明 | 输入参数逐行格式（`- **`name`** — type，必填/可选。说明。`），无外部输入参数时写 `- 无外部输入参数` |
| 产出文件命名 | 产出文件命名规则 |
| 结构声明 | 产物 spec 的 3 段式结构定义，含每段编写规则的子章节 |
| 必要章节 | 该类型文档必须包含的章节列表 |
